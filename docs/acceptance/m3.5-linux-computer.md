# M3.5 Linux-native Computer acceptance

This is the native Ubuntu authority for the Linux column of agent-computer
spec §10.2. It runs only after `acceptance-image` has published the exact main
commit's echo and reference Computer archives. The workflow downloads those
immutable artifacts, verifies their receipts and index digests, imports them
through the real root helper into pinned containerd, and then starts the real
L1, L3, agent, helper, and payload processes.

The test is `TestLinuxNativeComputerCLIMatrixAtProductionTimings` in
`serviceacceptance/computer_realtiming_test.go`. Operator mutations go through
the built `wefty` CLI. Direct Store access is used only to initiate the local
admin-bootstrap challenge, which is intentionally not a network operation;
the challenge is redeemed through the CLI.

## Receipt contract

The Ubuntu artifact contains `linux-computer-matrix.json`. Its seven stable
row IDs map one-to-one to spec §10.2:

| Stable row ID | Spec proof | Assertion boundary |
| --- | --- | --- |
| `linux.create_boot` | Create and boot | Digest-pinned trait-only Computer reaches atomic display readiness on a fully allocated disk. |
| `linux.remote_takeover` | Remote take-over | CLI policy CAS plus the required real-process front-door and viewer-input-denial assertions. |
| `linux.restart_survival` | Restart survival | Agent loss creates a fresh attempt on the same Storage generation and republishes readiness. |
| `linux.reconfiguration` | Reconfiguration | CLI grow, reset, and reimage converge; tagged stale-CAS and abort mutations remain load-bearing. |
| `linux.storage_provenance` | Storage provenance | CLI Backup, clone, custody export/import/attest, and restore retain bound provenance. |
| `linux.guest_authority` | Guest authority | CLI submission intent and portable token/scope/inflight matrices execute; the root-Run artifact remains structured `NOT-RUN` on #157. |
| `linux.removal` | Removal | Real helper cleanup distinguishes `removed_verified` from custody-reduced removal; the portable unverified outcome remains load-bearing. |

Each row starts as `NOT-RUN`, changes to `FAIL` immediately before its product
path executes, and changes to `PASS` only after every named assertion is true.
The aggregate can be `PASS` only when all seven rows contain executed assertion
maps and start/completion timestamps. This is the mutation boundary: breaking a
product path leaves its owning row `FAIL`; deleting the assertion-derived work
cannot manufacture `PASS`.

Receipts retain the candidate commit, image reference/index digest, platform,
Computer/Job/attempt/Storage IDs, revisions, production timings (in the sibling
`metadata.json`), and redacted process logs. They never record take-over
capabilities, Computer bearer values, framebuffer bytes, keystrokes, or tenant
content.

## Structured NOT-RUN

`NOT-RUN` is not destination success. The Darwin workflow artifact records all
Linux rows `NOT-RUN` because hosted Darwin is neither native Linux nor the
attended Mac/Lima authority. A missing immutable publication makes the
fail-closed `realtiming-result` job fail, so a typed skip cannot produce a green
workflow (#241).

The complete M3 OCI matrix is still tracked by #157 and itself retains the
owner-attended #128 dependency. This Linux lane does not wait for attended Mac
hardware. Any assertion that genuinely requires an unpublished #157 matrix
artifact remains `NOT-RUN` with `not_run_issue: 157`; it must not be copied into
a PASS row from unit-only evidence. Today that is the Computer-bearer root-Run
artifact in `linux.guest_authority`; its CLI submission mutation and portable
token/scope assertions still execute before the structured skip is recorded.

## Commands

The workflow command is:

```sh
go test -count=1 -p 1 -timeout=30m -v \
  -tags=service_acceptance_realtiming ./...
```

The PR-required portable and mutation coverage remains:

```sh
go test -p 1 -tags=service_acceptance ./...
```

Local macOS runs cannot execute the native lane. Compile it with both platform
authorities instead:

```sh
GOOS=linux go vet -tags=service_acceptance_realtiming ./...
GOOS=darwin go vet -tags=service_acceptance_realtiming ./...
```
