# M3.5 Linux-native Computer acceptance

This is the native Ubuntu authority for the Linux column of agent-computer
spec §10.2. The workflow downloads immutable echo and reference Computer build
artifacts, verifies their receipts and index digests, imports them through the
real root helper into pinned containerd, and then starts the real L1, L3,
agent, helper, and payload processes.

## Main and pull-request provenance

The main lane remains causally downstream of `acceptance-image`: it consumes
the exact archives promoted to public GHCR by the triggering main run and its
evidence receipt records `source=published-artifact`. The pull-request lane is
separate, path-filtered, non-required, and secretless. It builds the candidate
head's platform archives, combines those artifacts without a registry or
publish step, and records `source=pr-build`; `public_pull` is therefore false
in its image receipts. Forks run through `pull_request`, never
`pull_request_target`, so neither package-write credentials nor repository
secrets are reachable by the privileged hosted-VM helper.

Both event paths enter the same provisioning, production-timing test,
diagnostic capture, evidence upload, and `realtiming-result` blocks. Every
matrix artifact includes `provenance-receipt.json`, binding its source and
candidate commit to the image artifact run. The result gate checks that receipt
and then applies the same fail-closed XFCE and Wayland row checks. A manual
dispatch may target a PR head when an operator needs a fresh non-required
signal.

The test is `TestLinuxNativeComputerCLIMatrixAtProductionTimings` in
`serviceacceptance/computer_realtiming_test.go`. Operator mutations go through
the built `wefty` CLI. The harness initiates administration through the shipped
`wefty-l1 --initiate-admin-bootstrap` offline command before L1 starts, then
redeems that challenge through `wefty admin bootstrap`; it never opens a second
SQLite writer beside the live control plane.

## Receipt contract

The Ubuntu `image=xfce` and `image=wayland` matrix artifacts each contain a
`linux-computer-matrix.json`. The receipt pins its image variant and repeats
the same nine stable row IDs. Seven map one-to-one to spec §10.2; the two
isolation rows, `linux.network_egress` and `linux.screen_crossover_refused`,
were added beside them and mirror the Mac rows of the same names:

| Stable row ID | Spec proof | Assertion boundary |
| --- | --- | --- |
| `linux.create_boot` | Create and boot | The lane observes trait refusal, fully allocated disk blocks, and live view/control endpoint dials. |
| `linux.network_egress` | Private network outbound (added) | From inside the Computer: private veth address, mounted resolver, default route, public IPv4 connect, DNS resolve, and the helper HTTP marker through the veth; the helper control socket is absent from the Computer's mount namespace, and node loopback and node listeners (IPv4 and IPv6) are refused. |
| `linux.screen_crossover_refused` | Screen crossover refused (added) | Two co-located live Computers: dials from one to the other's view, control, and egress addresses are refused while the target is proven alive before and after, the temporary relay is cleaned up, the target's own loopback still works, and the neighbour removes `removed_verified`. |
| `linux.remote_takeover` | Remote take-over | Live CLI grant/view/take/release/admin-override/revoke/audit plus RFB pointer isolation through the running edge. |
| `linux.restart_survival` | Restart survival | Payload, shim, helper, containerd, and agent loss each create a fresh attempt while an on-disk marker survives and stale session authority dies. |
| `linux.reconfiguration` | Reconfiguration | Live grow/reset/reimage, a helper crash phase, stale CAS, dead-node abort, detachment evidence, and no automatic rollback. |
| `linux.storage_provenance` | Storage provenance | Live cold Backup, keep-old restore, clone/custody fork, export/import taint, stale capability rejection, cap pressure, and real-disk ENOSPC. |
| `linux.guest_authority` | Guest authority | The live pass drives `/self`, root submission and provenance, self-scoped listing, exact route denial, 20-inflight pressure, and a paused-request disable race; the lane then records the row `NOT-RUN` with `not_run_issue: 196` (see Structured NOT-RUN). |
| `linux.removal` | Removal | A read-only helper `VerifyNamespaceReadOnly` inventory independently proves managed residue absent without satisfying the boot barrier or mutating cache/pin state, binds `removed_reduced` to the custody-tainted Computer, and proves bind/cache preservation. |

Each row starts as `MISSING`, changes to `FAIL` immediately before its product
path executes, and changes to `PASS` only after every named assertion is true.
The only allowlisted row-level `NOT-RUN` is `linux.guest_authority` with
`not_run_issue: 196`, after its live assertions have executed; an unmutated
receipt therefore carries top-level `status: NOT-RUN` and `not_run_issue: 196`. The `realtiming-result` job downloads
and parses both Linux JSON receipts: a missing image dimension, `MISSING`,
`FAIL`, an unexpected `NOT-RUN`, a false assertion, or incomplete attribution
fails the workflow. A scheduled
`mutation_row` dispatch omits one owning product-path assertion and succeeds
only when exactly that stable row is `FAIL`.

Receipts retain the required candidate commit, image variant/reference/index/platform
digests, Computer/Job/attempt/Storage IDs, Fabric user/device IDs, policy and
authority generations, resource caps, timings, the plain-Fabric deviation, and
class-separated helper residue inventories. They never record take-over
capabilities, Computer bearer values, framebuffer bytes, keystrokes, or tenant
content.

The candidate-bound [Fabric-identity realtiming](fabric-identity-realtiming.md)
receipt is the independent production-Fabric authority for that deviation.
Only its live rows remove `dev.plain_fabric_identity`; the Linux lifecycle
receipt remains honest about its own self-asserted plain identities.

## The Linux half of the OCI acceptance matrix (#157)

The same `realtiming-result` job assembles the M3 OCI acceptance matrix (spec
section 9) from this lane's flat receipts — `native-linux-oci.txt`,
`oci-service-publication-linux.txt`, `oci-service-l1-agent-linux.txt`,
`helper-restart-timeline.txt` and `lost-attempt-sweep.txt` — bound to the
candidate through this lane's `provenance-receipt.json`, through
`scripts/assemble-oci-acceptance-matrix.sh`, and gates it with
`scripts/check-oci-acceptance-matrix.sh`. The matrix is uploaded as
`oci-acceptance-matrix-<sha>`. It is a separate concern from the Computer rows
above: it covers ordinary `kind=oci` cells, and every cell it cannot prove from
this lane carries a typed skip naming the missing evidence. The Mac half is
never claimed here; see [m3-lima-transport.md](m3-lima-transport.md).

## The Linux half of the Computer acceptance matrix (#196)

The same `realtiming-result` job also assembles the agent-computer acceptance
matrix (spec §10) from the XFCE `linux-computer-matrix.json` above — copied
verbatim, its nine rows and version 5 unchanged — through
`scripts/assemble-computer-acceptance-matrix.sh`, and gates it with
`scripts/check-computer-acceptance-matrix.sh`. The matrix is uploaded as
`computer-acceptance-matrix-<sha>`. Its Mac half comes from the attended
owner-hardware lane in [m3.5-mac-computer.md](m3.5-mac-computer.md); in CI that
half is absent, so every `mac.*` row is a typed `NOT-RUN` and the gate prints
`matrix incomplete: 10 Mac rows not run` without failing. A hosted runner can
never claim a Mac row.

## Structured NOT-RUN

`NOT-RUN` is not destination success. The Darwin workflow artifact records all
Linux rows `NOT-RUN` because hosted Darwin is neither native Linux nor the
attended Mac/Lima authority. A missing immutable publication makes the
fail-closed `realtiming-result` job fail, so a typed skip cannot produce a green
workflow (#241).

The complete M3 OCI matrix was tracked by #157, which is now closed; the
owner-attended #128 prototype remains open. This Linux lane does not wait for
attended Mac hardware. The lane still records one skip: `linux.guest_authority`
lacks a candidate-bound root Run execution result — a Run the Computer itself
submitted, driven to its terminal result. #157 was expected to publish one to
join here, but it closed covering only `kind=oci` job cells, never Runs, so
the row stays `NOT-RUN` with `not_run_issue: 196`, the open Computer matrix
ticket, and the receipt checker requires exactly that. Closing it needs this
lane to drive a Computer-submitted root Run to completion itself; the skip
must not be copied into a PASS row from unit-only evidence. The live Computer
bearer still drives route scope, provenance, capacity, and revocation
assertions before the structured skip is recorded.

## Commands

The workflow command is:

```sh
go test -count=1 -p 1 -timeout=75m -v \
  -tags=service_acceptance_realtiming ./...
```

Independent PR-required service-acceptance coverage remains; it is not counted
as Linux-native row evidence:

```sh
go test -p 1 -tags=service_acceptance ./...
```

Local macOS runs cannot execute the native lane. Compile it with both platform
authorities instead:

```sh
GOOS=linux go vet -tags=service_acceptance_realtiming ./...
GOOS=darwin go vet -tags=service_acceptance_realtiming ./...
```
