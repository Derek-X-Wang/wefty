# Service-class real-timing acceptance (v0.2)

This is the owner-run evidence lane for service-class jobs. Run the complete
procedure once on native Darwin hardware and once on native Linux hardware at
the accepted commit. It deliberately kills payload and agent processes, uses a
real tailnet, and is evidence, not a merge gate.

Do not compress clocks. Use the production defaults: a 30-second effective
lease, 15-second heartbeat, at-most-10-second renewal interval, 30-second
startup-readiness deadline, 250-millisecond probe interval, and 5-second
termination grace. No L3 daemon participates. A service is an L1 job, not a
run, and every create response must omit `run_id`.

## Why this still exists after CI

The `service-acceptance` job runs on Darwin and Linux on every pull request
with compressed clocks. It already proves the state-machine logic, fenced
attempt replacement, publication withdrawal/recovery, guardian reaping, CLI
create/list/status/restart/stop/remove behavior, multi-service and one-shot
slot isolation, removal from every state, force-forget, acknowledgement replay,
retention, and the destructive-deletion guardrail matrix. Targeted tagged tests
also prove that a portless service stays alive without entering readiness or
proxy machinery; the twelve steps below intentionally skip portless services
because their only observable surface is process liveness.

CI uses one-second leases and short polling intervals. It proves the logic,
not production timing. This procedure supplies the evidence CI cannot:

- the same behavior at the production lease, renewal, heartbeat, probe, and
  termination intervals;
- native process/signal behavior on the owner's Darwin and Linux hardware;
- guardian reaping before lease expiry after a real agent `SIGKILL`;
- DNS, ACL, and TCP reachability from another machine through the node's real
  tailnet hostname.

## Prerequisites and fresh state

Use an otherwise idle test node and a second physical tailnet peer. The test
node must itself be joined to the tailnet. ACLs must allow
`tag:wefty-client` to reach `tag:wefty-agent` on ports 18080-18083 and
`tag:wefty-agent` to reach `tag:wefty-control:80`. Install the Go version in
`go.mod`, `jq`, `curl`, and `sqlite3`.

Export reusable, pre-authorized keys in the shell without writing them into
the repository:

```sh
export TS_AUTHKEY_CONTROL='...'
export TS_AUTHKEY_AGENT='...'
export TS_AUTHKEY_CLIENT='...'
export TS_CONTROL_URL="${TS_CONTROL_URL:-}"
```

In one orchestration shell on the test node, set `PLATFORM` to `darwin` or
`linux` and create a new empty root. Never reuse an old database; pre-1.0
schema changes do not migrate it.

```sh
set -eu
set -o pipefail

export WEFTY_ROOT="$(git rev-parse --show-toplevel)"
export PLATFORM=darwin                    # use linux for the Linux run
export NODE_ID="services-${PLATFORM}"
export SERVICE_PORT=18080
export SIBLING_PORT=18081
export FAILED_PORT=18082
export OFFLINE_PORT=18083
export EFFECTIVE_LEASE_SECONDS=30

export ACCEPTANCE_ROOT="$(mktemp -d "${TMPDIR:-/tmp}/wefty-services-${PLATFORM}.XXXXXX")"
export STATE_ROOT="$ACCEPTANCE_ROOT/state"
export EVIDENCE="$ACCEPTANCE_ROOT/evidence"
export BIN="$ACCEPTANCE_ROOT/bin"
export WORKING_DIRECTORY="$ACCEPTANCE_ROOT/operator-owned"
export MANAGED_ROOT="$STATE_ROOT/managed"
export SPOOL_DIRECTORY="$STATE_ROOT/spool"
export HANDOFF_ROOT="$STATE_ROOT/handoffs"
export L1_DATABASE="$STATE_ROOT/l1.sqlite"
export TMPDIR="$STATE_ROOT/tmp"
mkdir -p "$BIN" "$EVIDENCE" "$WORKING_DIRECTORY" "$MANAGED_ROOT" \
  "$SPOOL_DIRECTORY" "$HANDOFF_ROOT" "$TMPDIR"
printf 'operator-owned; removal must not alter this\n' > "$WORKING_DIRECTORY/sentinel"

git -C "$WEFTY_ROOT" status --short > "$EVIDENCE/git-status-before.txt"
test ! -s "$EVIDENCE/git-status-before.txt"
git -C "$WEFTY_ROOT" rev-parse HEAD | tee "$EVIDENCE/commit.txt"
uname -a | tee "$EVIDENCE/platform.txt"
```

Preserve `ACCEPTANCE_ROOT` after the run; it is the evidence bundle.

## 1. Build

```sh
cd "$WEFTY_ROOT"
go build -o "$BIN/wefty-l1" ./cmd/wefty-l1
go build -o "$BIN/wefty-agent" ./cmd/wefty-agent
go build -o "$BIN/wefty" ./cmd/wefty
go build -o "$BIN/wefty-echo-service" ./cmd/wefty-echo-service
```

The in-repository echo service reports its PID and injected backend port from
`/healthz`, echoes request bytes from `/echo`, emits one startup log event per
attempt, and handles `SIGTERM` with `http.Server.Shutdown`.

## 2. Start L1 and one stable node

Start L1 with the production lease stated explicitly and the owner-selected
4/2 class capacities:

```sh
cd "$WEFTY_ROOT"
"$BIN/wefty-l1" \
  --fabric=tsnet \
  --listen=wefty://control-plane \
  --fabric-name=wefty://control-plane \
  --state-dir="$STATE_ROOT/l1-tsnet" \
  --auth-key="$TS_AUTHKEY_CONTROL" \
  --control-url="$TS_CONTROL_URL" \
  --db="$L1_DATABASE" \
  --lease-duration=30s \
  --node-tags="$NODE_ID=service-acceptance" \
  --node-max-oneshot-slots="$NODE_ID=4" \
  --node-max-service-slots="$NODE_ID=2" \
  --ready-file="$STATE_ROOT/l1-ready.json" \
  > "$EVIDENCE/l1.log" 2>&1 &
L1_PID=$!
export L1_PID
printf '%s\n' "$L1_PID" > "$EVIDENCE/l1.pid"
for _ in $(seq 1 120); do
  test -s "$STATE_ROOT/l1-ready.json" && break
  kill -0 "$L1_PID"
  sleep 1
done
test -s "$STATE_ROOT/l1-ready.json"
wc -c < "$L1_DATABASE" | tee "$EVIDENCE/l1-size-before.txt"
```

Define reusable agent and CLI commands. Their omitted timing flags are
intentional: production defaults are under acceptance.

```sh
start_agent() {
  cd "$WEFTY_ROOT"
  "$BIN/wefty-agent" \
    --fabric=tsnet \
    --control-plane=wefty://control-plane \
    --node-id="$NODE_ID" \
    --fabric-name="wefty://node/$NODE_ID" \
    --state-dir="$STATE_ROOT/agent-tsnet" \
    --auth-key="$TS_AUTHKEY_AGENT" \
    --control-url="$TS_CONTROL_URL" \
    --log-spool-dir="$SPOOL_DIRECTORY" \
    --managed-root="$MANAGED_ROOT" \
    --handoff-root="$HANDOFF_ROOT" \
    > "$EVIDENCE/agent-$(date +%s).log" 2>&1 &
  AGENT_PID=$!
  export AGENT_PID
  printf '%s\n' "$AGENT_PID" > "$EVIDENCE/agent-current.pid"
}

wefty() {
  "$BIN/wefty" \
    --fabric=tsnet \
    --fabric-name="wefty://node/${NODE_ID}-operator" \
    --state-dir="$STATE_ROOT/operator-tsnet" \
    --auth-key="$TS_AUTHKEY_CLIENT" \
    --control-url="$TS_CONTROL_URL" \
    "$@"
}

start_agent
for _ in $(seq 1 120); do
  wefty --json nodes list > "$EVIDENCE/nodes.json" 2>/dev/null || true
  jq -e --arg node "$NODE_ID" \
    '.nodes[] | select(.node_id == $node and .state == "alive" and .claims_enabled == true)' \
    "$EVIDENCE/nodes.json" >/dev/null 2>&1 && break
  kill -0 "$AGENT_PID"
  sleep 1
done
jq -e --arg node "$NODE_ID" \
  '.nodes[] | select(.node_id == $node and .state == "alive" and .claims_enabled == true and .max_service_slots == 2)' \
  "$EVIDENCE/nodes.json"
CONNECT_HOST="$(jq -er --arg node "$NODE_ID" '.nodes[] | select(.node_id == $node) | .connect_host' "$EVIDENCE/nodes.json")"
export CONNECT_HOST
```

## 3. Create two resident service jobs

The sibling remains resident while the primary is killed and restarted.
Create both from the operator-owned directory so removal can prove it is
untouched.

```sh
cd "$WORKING_DIRECTORY"
wefty --json services create \
  --script="$BIN/wefty-echo-service" --mode=0755 \
  --tag=service-acceptance --published-port="$SERVICE_PORT" \
  --idempotency-key="services-${PLATFORM}-primary" \
  | tee "$EVIDENCE/create-primary.json"
jq -e '(has("run_id") | not) and (.job_id | type == "string" and length > 0)' \
  "$EVIDENCE/create-primary.json"
JOB_ID="$(jq -er .job_id "$EVIDENCE/create-primary.json")"
export JOB_ID

wefty --json services create \
  --script="$BIN/wefty-echo-service" --mode=0755 \
  --tag=service-acceptance --published-port="$SIBLING_PORT" \
```

## 6. `SIGKILL` the payload and observe restart-pending

Capture status before disruption, kill exactly the PID reported by
`/healthz`, and poll fast enough to see the first production backoff window.

```sh
wefty --json services status "$JOB_ID" | tee "$EVIDENCE/status-before-payload-kill.json"
kill -KILL "$PID_1"
for _ in $(seq 1 100); do
  wefty --json services status "$JOB_ID" > "$EVIDENCE/status-restart-pending.json"
  jq -e '
    .state == "queued" and .status == "restart-pending" and
    .ready == false and (has("published_port") | not) and
    (.next_restart_at | type == "string" and length > 0)
  ' "$EVIDENCE/status-restart-pending.json" >/dev/null && break
  sleep 0.1
done
jq -e '.status == "restart-pending" and .next_restart_at != null' \
  "$EVIDENCE/status-restart-pending.json"
if curl --connect-timeout 1 --max-time 2 --silent --show-error \
  "http://${CONNECT_HOST}:${SERVICE_PORT}/healthz" >/dev/null 2>&1; then
  echo 'published endpoint remained reachable during restart-pending' >&2
  exit 1
fi

for _ in $(seq 1 120); do
  wefty --json services status "$JOB_ID" > "$EVIDENCE/status-after-payload-kill.json"
  jq -e --arg old "$ATTEMPT_1" '
    .state == "running" and .ready == true and
    (.current_attempt_id | length > 0) and .current_attempt_id != $old
  ' "$EVIDENCE/status-after-payload-kill.json" >/dev/null && break
  sleep 1
done
ATTEMPT_2="$(jq -er .current_attempt_id "$EVIDENCE/status-after-payload-kill.json")"
curl --fail --silent --show-error \
  "http://${CONNECT_HOST}:${SERVICE_PORT}/healthz" \
  | tee "$EVIDENCE/health-primary-2.json"
PID_2="$(jq -er '.pid | select(. > 0)' "$EVIDENCE/health-primary-2.json")"
test "$ATTEMPT_2" != "$ATTEMPT_1"
test "$PID_2" != "$PID_1"
jq -e --arg node "$NODE_ID" --argjson port "$SERVICE_PORT" \
  '.bound_node_id == $node and .published_port == $port' \
  "$EVIDENCE/status-after-payload-kill.json"

# The resident sibling must be untouched.
wefty --json services status "$SIBLING_JOB_ID" > "$EVIDENCE/status-sibling-after-payload-kill.json"
jq -e --arg attempt "$SIBLING_ATTEMPT_1" \
  '.state == "running" and .ready == true and .current_attempt_id == $attempt' \
  "$EVIDENCE/status-sibling-after-payload-kill.json"
test "$(curl --fail --silent --show-error \
  "http://${CONNECT_HOST}:${SIBLING_PORT}/healthz" | jq -er .pid)" = "$SIBLING_PID_1"
export ATTEMPT_2 PID_2
```


## 8. `SIGKILL` the agent, prove guardian reaping, and recover

The guardian must remove both resident payloads before the 30-second lease
expires. Do not wait for the control plane to declare the node stale.

```sh
wefty --json services status "$JOB_ID" | tee "$EVIDENCE/status-before-agent-kill.json"
KILL_STARTED="$(date +%s)"
kill -KILL "$AGENT_PID"
wait "$AGENT_PID" 2>/dev/null || true
for _ in $(seq 1 300); do
  if ! kill -0 "$PID_3" 2>/dev/null && ! kill -0 "$SIBLING_PID_1" 2>/dev/null; then
    break
  fi
  sleep 0.1
done
KILL_ELAPSED="$(( $(date +%s) - KILL_STARTED ))"
test "$KILL_ELAPSED" -lt "$EFFECTIVE_LEASE_SECONDS"
if kill -0 "$PID_3" 2>/dev/null || kill -0 "$SIBLING_PID_1" 2>/dev/null; then
  echo 'guardian left an orphan payload after agent SIGKILL' >&2
  exit 1
fi
if curl --connect-timeout 1 --max-time 2 --silent --show-error \
  "http://${CONNECT_HOST}:${SERVICE_PORT}/healthz" >/dev/null 2>&1; then
  echo 'published endpoint survived agent SIGKILL' >&2
  exit 1
fi
printf 'guardian_reap_seconds=%s effective_lease_seconds=%s\n' \
  "$KILL_ELAPSED" "$EFFECTIVE_LEASE_SECONDS" \
  | tee "$EVIDENCE/guardian-timing.txt"

start_agent
for _ in $(seq 1 180); do
  wefty --json services status "$JOB_ID" > "$EVIDENCE/status-after-agent-restart.json"
  jq -e --arg old "$ATTEMPT_3" '
    .state == "running" and .ready == true and
    (.current_attempt_id | length > 0) and .current_attempt_id != $old
  ' "$EVIDENCE/status-after-agent-restart.json" >/dev/null && break
  kill -0 "$AGENT_PID"
  sleep 1
done
ATTEMPT_4="$(jq -er .current_attempt_id "$EVIDENCE/status-after-agent-restart.json")"
PID_4="$(curl --fail --silent --show-error \
  "http://${CONNECT_HOST}:${SERVICE_PORT}/healthz" | jq -er '.pid | select(. > 0)')"
test "$ATTEMPT_4" != "$ATTEMPT_3"
test "$PID_4" != "$PID_3"
! kill -0 "$PID_3" 2>/dev/null
export ATTEMPT_4 PID_4

for _ in $(seq 1 180); do
  wefty --json services status "$SIBLING_JOB_ID" > "$EVIDENCE/status-sibling-after-agent-restart.json"
  jq -e --arg old "$SIBLING_ATTEMPT_1" '
    .state == "running" and .ready == true and .current_attempt_id != $old
  ' "$EVIDENCE/status-sibling-after-agent-restart.json" >/dev/null && break
  sleep 1
done
jq -e --arg node "$NODE_ID" --argjson port "$SERVICE_PORT" \
  '.bound_node_id == $node and .published_port == $port' \
  "$EVIDENCE/status-after-agent-restart.json"
```

## 10. Stop, wait past authority timing, and prove no restart

```sh
wefty --json services status "$JOB_ID" | tee "$EVIDENCE/status-before-stop.json"
ATTEMPTS_BEFORE_STOP="$(jq '.attempts | length' "$EVIDENCE/status-before-stop.json")"
RESTARTS_BEFORE_STOP="$(jq .lifetime_restart_count "$EVIDENCE/status-before-stop.json")"
PGID_4="$(ps -o pgid= -p "$PID_4" | tr -d ' ')"
wefty --json services stop "$JOB_ID" --wait=30s \
  | tee "$EVIDENCE/status-stopped.json"
jq -e '
  .state == "stopped" and .desired_state == "stopped" and
  .holds_slot == false and .ready == false and
  (has("published_port") | not)
' "$EVIDENCE/status-stopped.json"
! kill -0 "$PID_4" 2>/dev/null
! kill -0 -- "-$PGID_4" 2>/dev/null
if curl --connect-timeout 1 --max-time 2 --silent --show-error \
  "http://${CONNECT_HOST}:${SERVICE_PORT}/healthz" >/dev/null 2>&1; then
  echo 'published port remained after stop' >&2
  exit 1
fi

# One effective lease plus two production probe intervals is 30.5 seconds.
sleep 31
wefty --json services status "$JOB_ID" | tee "$EVIDENCE/status-after-stop-wait.json"
jq -e --argjson attempts "$ATTEMPTS_BEFORE_STOP" --argjson restarts "$RESTARTS_BEFORE_STOP" '
  .state == "stopped" and .desired_state == "stopped" and
  (.attempts | length) == $attempts and .lifetime_restart_count == $restarts
' "$EVIDENCE/status-after-stop-wait.json"
```

Resume the primary service, wait for a new ready attempt, then run the endpoint
checks from a different physical machine. Do not use another shell on the
service node.


On the remote peer, substitute the recorded hostname and port:

```sh
curl --fail --silent --show-error \
```

Copy those four files into `EVIDENCE`, record the remotely observed PID, then

```sh
PID_5="$(jq -er '.pid | select(. > 0)' "$EVIDENCE/health-remote.json")"
test "$PID_5" != "$PID_4"
printf 'attempt=%s payload_pid=%s node=%s port=%s\n' \

```

On the remote peer, prove that withdrawal also traverses the tailnet. Copy the
captured stderr file into `EVIDENCE`.

```sh
if curl --connect-timeout 2 --max-time 3 --silent --show-error \
  "http://CONNECT_HOST:SERVICE_PORT/healthz" \
  > health-after-stop.json 2> health-after-stop.stderr; then
  echo 'remote tailnet endpoint remained after stop' >&2
  exit 1
fi
```

This is the assertion the PR lane cannot make: the successful call traversed
real tailnet DNS and ACLs from a separate client to the published listener.

```sh
    '[.events[] | select(.attempt_id == $attempt)] | length > 0' \

done

SPOOL_DATABASE="$(find "$SPOOL_DIRECTORY" -type f -name '*.sqlite' -print -quit)"
test -n "$SPOOL_DATABASE"
{
  printf 'l1_database_bytes='; wc -c < "$L1_DATABASE"
  printf 'l1_wal_bytes='; test -f "$L1_DATABASE-wal" && wc -c < "$L1_DATABASE-wal" || printf '0\n'

  sqlite3 "$L1_DATABASE" "SELECT 'log_events', count(*) FROM log_events;"
  sqlite3 "$L1_DATABASE" "SELECT 'primary_jsonl_bytes', length(jsonl) FROM job_log_jsonl WHERE job_id='$JOB_ID';"
  printf 'spool_database_bytes='; wc -c < "$SPOOL_DATABASE"
  sqlite3 "$SPOOL_DATABASE" "SELECT 'spool_attempts', count(*) FROM spool_attempts;"
} | tee "$EVIDENCE/residue-before-removal.txt"
```

Record all status JSON before and after each disruption, every attempt ID and
payload PID, both logs views, platform, commit, and guardian elapsed time. L1
database size, the `jobs`/`attempts`/`log_events` row counts, per-job JSONL
blob size, spool size, and `spool_attempts` count are measurements only. They
have no ratified pass/fail threshold; they inform whether the 32 MiB and
seven-day retention bounds are sensible.

## Removal and residue coverage

Perform these checks in the same run. They deliberately exercise running,
stopped, latched-failed, and offline removal separately.

### Remove a running service

The sibling is still healthy. Remove it while running and require an
agent-confirmed tombstone, not merely a control-plane request.

```sh
wefty --json services status "$SIBLING_JOB_ID" \
  | tee "$EVIDENCE/status-sibling-before-remove.json"
jq -e '.state == "running" and .ready == true' \
  "$EVIDENCE/status-sibling-before-remove.json"
wefty --json services remove "$SIBLING_JOB_ID" --wait=60s \
  | tee "$EVIDENCE/status-sibling-removed.json"
jq -e '
  .state == "removed_verified" and
  .status == "removed (agent-confirmed)" and
  .removal.removal_outcome == "verified_removed"
' "$EVIDENCE/status-sibling-removed.json"
```

Confirm its port, process tree, managed service root, attempt spool rows, and
log rows are gone. The tagged CI lane already covers secret scrubbing; this
public CLI flow does not accept a `SensitiveEnv` value to expose to the shell.

```sh
if curl --connect-timeout 1 --max-time 2 --silent --show-error \
  "http://${CONNECT_HOST}:${SIBLING_PORT}/healthz" >/dev/null 2>&1; then
  echo 'sibling port remained after removal' >&2
  exit 1
fi
test "$(sqlite3 "$L1_DATABASE" "SELECT count(*) FROM jobs WHERE job_id='$SIBLING_JOB_ID';")" = 0
test "$(sqlite3 "$L1_DATABASE" "SELECT count(*) FROM attempts WHERE job_id='$SIBLING_JOB_ID';")" = 0
test "$(sqlite3 "$L1_DATABASE" "SELECT count(*) FROM log_events WHERE job_id='$SIBLING_JOB_ID';")" = 0
test "$(sqlite3 "$SPOOL_DATABASE" "SELECT count(*) FROM spool_attempts WHERE job_id='$SIBLING_JOB_ID';")" = 0
```

### Remove a stopped service and replay create

The primary was stopped in step 11. Remove it, then repeat the byte-identical
create under the same idempotency key. The replay must return the original
verified tombstone and must not create another service.

```sh
wefty --json services status "$JOB_ID" \
  | tee "$EVIDENCE/status-primary-before-remove.json"
jq -e '.state == "stopped" and .desired_state == "stopped"' \
  "$EVIDENCE/status-primary-before-remove.json"
wefty --json services remove "$JOB_ID" --wait=60s \
  | tee "$EVIDENCE/status-primary-removed.json"
jq -e --arg job "$JOB_ID" '
  .job_id == $job and .state == "removed_verified" and
  .status == "removed (agent-confirmed)" and
  .removal.removal_outcome == "verified_removed"
' "$EVIDENCE/status-primary-removed.json"

cd "$WORKING_DIRECTORY"
wefty --json services create \
  --script="$BIN/wefty-echo-service" \
  --mode=0755 \
  --tag=service-acceptance \
  --published-port="$SERVICE_PORT" \
  --idempotency-key="services-${PLATFORM}-primary" \
  | tee "$EVIDENCE/create-primary-replay.json"
jq -e --arg job "$JOB_ID" '
  .job_id == $job and .state == "removed_verified" and
  (has("run_id") | not)
' "$EVIDENCE/create-primary-replay.json"
test "$(sqlite3 "$L1_DATABASE" "SELECT count(*) FROM service_tombstones WHERE job_id='$JOB_ID' AND outcome='verified_removed';")" = 1
```

### Remove a latched-failed service

Create a payload that cannot be executed. Wait for the restart budget to
latch the service in `failed`, record the structured failure, then remove it.

```sh
printf 'not an executable file format\n' > "$EVIDENCE/failing-service"
chmod 0755 "$EVIDENCE/failing-service"
cd "$WORKING_DIRECTORY"
wefty --json services create \
  --script="$EVIDENCE/failing-service" \
  --mode=0755 \
  --tag=service-acceptance \
  --published-port="$FAILED_PORT" \
  --idempotency-key="services-${PLATFORM}-latched-failed" \
  | tee "$EVIDENCE/create-latched-failed.json"
FAILED_JOB_ID="$(jq -r .job_id "$EVIDENCE/create-latched-failed.json")"
export FAILED_JOB_ID

for _ in $(seq 1 120); do
  wefty --json services status "$FAILED_JOB_ID" \
    | tee "$EVIDENCE/status-latched-failed.json"
  jq -e '.state == "failed" and .last_failure != null' \
    "$EVIDENCE/status-latched-failed.json" >/dev/null && break
  sleep 1
done
jq -e '.state == "failed" and .last_failure != null and .holds_slot == false' \
  "$EVIDENCE/status-latched-failed.json"
wefty --json services remove "$FAILED_JOB_ID" --wait=60s \
  | tee "$EVIDENCE/status-latched-failed-removed.json"
jq -e '
  .state == "removed_verified" and
  .status == "removed (agent-confirmed)"
' "$EVIDENCE/status-latched-failed-removed.json"
```

### Remove while offline, force-forget, and replay the attestation

Create one final healthy service and record its managed root. Kill the agent,
which must cause the guardian to reap the payload, then request removal while
the node is offline.

```sh
cd "$WORKING_DIRECTORY"
wefty --json services create \
  --script="$BIN/wefty-echo-service" \
  --mode=0755 \
  --tag=service-acceptance \
  --published-port="$OFFLINE_PORT" \
  --idempotency-key="services-${PLATFORM}-offline-remove" \
  | tee "$EVIDENCE/create-offline-remove.json"
OFFLINE_JOB_ID="$(jq -r .job_id "$EVIDENCE/create-offline-remove.json")"
export OFFLINE_JOB_ID
for _ in $(seq 1 120); do
  wefty --json services status "$OFFLINE_JOB_ID" \
    | tee "$EVIDENCE/status-offline-ready.json"
  jq -e '.state == "running" and .ready == true' \
    "$EVIDENCE/status-offline-ready.json" >/dev/null && break
  sleep 1
done
curl --fail --silent --show-error \
  "http://${CONNECT_HOST}:${OFFLINE_PORT}/healthz" \
  | tee "$EVIDENCE/health-offline-remove.json"
OFFLINE_PID="$(jq -r .pid "$EVIDENCE/health-offline-remove.json")"
OFFLINE_MANIFEST="$(find "$MANAGED_ROOT" -name ownership-manifest -exec grep -l "$OFFLINE_JOB_ID" {} \;)"
test "$(printf '%s\n' "$OFFLINE_MANIFEST" | grep -c .)" = 1
OFFLINE_SERVICE_ROOT="$(dirname "$OFFLINE_MANIFEST")"
test -d "$OFFLINE_SERVICE_ROOT"

AGENT_KILLED_AT="$(date +%s)"
kill -KILL "$AGENT_PID"
wait "$AGENT_PID" 2>/dev/null || true
for _ in $(seq 1 100); do
  ! kill -0 "$OFFLINE_PID" 2>/dev/null && break
  sleep 0.1
done
GUARDIAN_OFFLINE_SECONDS="$(( $(date +%s) - AGENT_KILLED_AT ))"
printf '%s\n' "$GUARDIAN_OFFLINE_SECONDS" \
  | tee "$EVIDENCE/guardian-offline-remove-seconds.txt"
test "$GUARDIAN_OFFLINE_SECONDS" -lt "$EFFECTIVE_LEASE_SECONDS"

wefty --json services remove "$OFFLINE_JOB_ID" \
  | tee "$EVIDENCE/status-offline-removal-pending.json"
jq -e '
  .state == "removal_pending" and
  (.status | contains("clean") | not)
' "$EVIDENCE/status-offline-removal-pending.json"
sleep 31
wefty --json services status "$OFFLINE_JOB_ID" \
  | tee "$EVIDENCE/status-offline-still-pending.json"
jq -e '
  .state == "removal_pending" and
  (.status | contains("clean") | not)
' "$EVIDENCE/status-offline-still-pending.json"
test -d "$OFFLINE_SERVICE_ROOT"
```

`removal_pending` is deliberately not reported as clean. Force-forget waives
proof but does not cancel the deletion directive. The database row and local
root must therefore remain until the same stable node returns.

```sh
wefty --json services forget "$OFFLINE_JOB_ID" --force \
  | tee "$EVIDENCE/status-offline-force-forgotten.json"
jq -e '
  .state == "forgotten_cleanup_unverified" and
  .removal.removal_outcome == "force_forgotten"
' "$EVIDENCE/status-offline-force-forgotten.json"
test "$(sqlite3 "$L1_DATABASE" "SELECT count(*) FROM service_removals WHERE job_id='$OFFLINE_JOB_ID' AND status='forgotten_cleanup_unverified';")" = 1
test -d "$OFFLINE_SERVICE_ROOT"

start_agent
for _ in $(seq 1 120); do
  wefty --json services status "$OFFLINE_JOB_ID" \
    | tee "$EVIDENCE/status-force-forgotten-after-return.json"
  ACKNOWLEDGED="$(jq -r '.removal.cleanup_acknowledged_at // empty' \
    "$EVIDENCE/status-force-forgotten-after-return.json")"
  test -n "$ACKNOWLEDGED" && test ! -e "$OFFLINE_SERVICE_ROOT" && break
  kill -0 "$AGENT_PID"
  sleep 1
done
jq -e '
  .state == "forgotten_cleanup_unverified" and
  .removal.cleanup_acknowledged_at != null
' "$EVIDENCE/status-force-forgotten-after-return.json"
test ! -e "$OFFLINE_SERVICE_ROOT"
```

The force-forgotten directive remains standing. On the next production
heartbeat in the same boot, the agent processes it again and submits the same
acknowledgement body under the identical idempotency key. Capture the durable
fields before and after that automatic replay; they must not change.

```sh
sqlite3 -separator '|' "$L1_DATABASE" \
  "SELECT cleanup_acknowledgement_key, cleanup_acknowledgement_hash, agent_cleaned_ns FROM service_removals WHERE job_id='$OFFLINE_JOB_ID';" \
  | tee "$EVIDENCE/removal-ack-before-replay.txt"
test -s "$EVIDENCE/removal-ack-before-replay.txt"
sleep 31
kill -0 "$AGENT_PID"
sqlite3 -separator '|' "$L1_DATABASE" \
  "SELECT cleanup_acknowledgement_key, cleanup_acknowledgement_hash, agent_cleaned_ns FROM service_removals WHERE job_id='$OFFLINE_JOB_ID';" \
  | tee "$EVIDENCE/removal-ack-after-replay.txt"
cmp "$EVIDENCE/removal-ack-before-replay.txt" \
  "$EVIDENCE/removal-ack-after-replay.txt"
```

### Final residue assertions and shutdown

These are pass/fail assertions. Operator-owned files must survive, while no
removed service may retain a process, port, managed root, handoff, or spool
row. L1 and agent infrastructure state itself is expected to remain as
evidence.

```sh
grep -qx 'operator-owned; removal must not alter this' \
  "$WORKING_DIRECTORY/sentinel"
for job in "$JOB_ID" "$SIBLING_JOB_ID" "$FAILED_JOB_ID" "$OFFLINE_JOB_ID"; do
  if find "$MANAGED_ROOT" -name ownership-manifest -exec grep -l "$job" {} \; \
    | grep .; then
    echo "managed root remained for $job" >&2
    exit 1
  fi
  test "$(sqlite3 "$SPOOL_DATABASE" "SELECT count(*) FROM spool_attempts WHERE job_id='$job';")" = 0
done
test -z "$(find "$HANDOFF_ROOT" -mindepth 1 -print -quit)"
test -z "$(find "$TMPDIR" -name 'wefty-executable-*' -print -quit)"
for port in "$SERVICE_PORT" "$SIBLING_PORT" "$FAILED_PORT" "$OFFLINE_PORT"; do
  if curl --connect-timeout 1 --max-time 2 --silent --show-error \
    "http://${CONNECT_HOST}:${port}/healthz" >/dev/null 2>&1; then
    echo "published port $port remained" >&2
    exit 1
  fi
done

{
  printf 'l1_database_bytes='; wc -c < "$L1_DATABASE"
  printf 'l1_wal_bytes='; test -f "$L1_DATABASE-wal" && wc -c < "$L1_DATABASE-wal" || printf '0\n'
  sqlite3 "$L1_DATABASE" "SELECT 'jobs', count(*) FROM jobs;"
  sqlite3 "$L1_DATABASE" "SELECT 'attempts', count(*) FROM attempts;"
  sqlite3 "$L1_DATABASE" "SELECT 'log_events', count(*) FROM log_events;"
  sqlite3 "$L1_DATABASE" "SELECT 'primary_jsonl_bytes', coalesce((SELECT length(jsonl) FROM job_log_jsonl WHERE job_id='$JOB_ID'), 0);"
  printf 'spool_database_bytes='; wc -c < "$SPOOL_DATABASE"
  sqlite3 "$SPOOL_DATABASE" "SELECT 'spool_attempts', count(*) FROM spool_attempts;"
} | tee "$EVIDENCE/residue-after-removal.txt"

kill -TERM "$AGENT_PID"
sleep 1
kill -TERM "$AGENT_PID" 2>/dev/null || true
wait "$AGENT_PID" 2>/dev/null || true
kill -TERM "$L1_PID"
wait "$L1_PID" 2>/dev/null || true
git -C "$WEFTY_ROOT" status --short > "$EVIDENCE/git-status-after.txt"
test ! -s "$EVIDENCE/git-status-after.txt"
```

The final size and row-count block remains observational, not pass/fail. The
run fails if any earlier assertion fails or if the evidence bundle lacks a
status snapshot before and after each disruption, all attempt IDs and PIDs,
logs for every attempt, the tailnet peer request/response, platform, and exact
commit.
