# v0.2 fleet setup — the steps only you can do

Everything scriptable I'll drive; this is the human-only list. Order matters.
Reference lane: docs/acceptance/v0.1-dogfood.md, v0.2 section.

## A. Tailscale admin console (~10 min) — https://login.tailscale.com/admin

**A1. Declare the tags** — Access Controls → edit policy, add to `tagOwners`:

```jsonc
"tagOwners": {
  "tag:wefty-client": ["autogroup:admin"],
  "tag:wefty-agent":  ["autogroup:admin"],
  "tag:wefty-control": ["autogroup:admin"]
}
```

Keep `tag:wefty-agent` ownership limited to administrators. Do not let ordinary
members or a group they can edit assign this tag: it grants work admission
when automatic Node admission is enabled.

**A2. Check ACL reachability.** Personal tailnets default to allow-all — if
you've never edited ACLs beyond tagOwners, you're done. If you have custom
rules, ensure `tag:wefty-client` and `tag:wefty-agent` can reach
`tag:wefty-control:80` and each other on 80.

**A3. Create each join key immediately before enrolment** — Settings → Keys →
Generate auth key. Each key is **single-use (Reusable ✗), Pre-authorized ✓,
Ephemeral ✗**, with a short expiry. Create it just before the corresponding
participant enrols, rather than making all keys in advance:

| Key name (your notes)   | Tags              |
|-------------------------|-------------------|
| TS_AUTHKEY_CONTROL      | tag:wefty-control |
| TS_AUTHKEY_CLIENT       | tag:wefty-client  |
| TS_AUTHKEY_AGENT_MAC    | tag:wefty-agent   |
| TS_AUTHKEY_AGENT_LINUX  | tag:wefty-agent   |

Use the no-echo enrolment prompt. Never paste keys into files in the repo.
The earlier reusable, 90-day agent-key instructions are superseded by the
[#900 automatic admission contract](../contracts/lease-fencing-dispatch.md#automatic-node-admission).
L1 cannot check key reuse, expiry, creation time, or tag ownership for you.

## B. MacBook-2 prep (~20 min, at that machine)

1. Install if missing: Xcode CLT (`xcode-select --install`), Homebrew, then
   `brew install go node@22 jq git`.
2. Install + **authenticate** both agent CLIs (interactive — only you):
   `npm i -g @anthropic-ai/claude-code` → run `claude` once, log in;
   Codex per your usual install → run `codex` once, log in.
3. `git clone https://github.com/Derek-X-Wang/wefty.git ~/wefty`
4. Sanity: `cd ~/wefty && go build ./... && cd workflows/dogfood && npm ci && npm test`

## C. Linux server prep (~20 min, SSH)

1. Install: Go ≥ go.mod version, Node 22 (nvm or NodeSource), `jq`, `git`.
2. Install + authenticate `claude` and `codex` CLIs for non-interactive use
   (device-code login over SSH works for both).
3. `git clone https://github.com/Derek-X-Wang/wefty.git /srv/wefty`
4. Same sanity build as B4.

## D. Arm the CI tsnet lane (~2 min, your terminal — key touches your shell only)

This historical CI step applies only to the legacy lane with automatic Node
admission disabled. It is superseded for fleet automatic admission by the
[admission preconditions](../contracts/lease-fencing-dispatch.md#automatic-node-admission).
Do not reuse a fleet agent join key as a standing CI secret. Per-run CI
enrolment is outside this fleet checklist and needs its own credential plan.

Type these with the `!` prefix in this Claude Code session (runs as you;
the key value never passes through me):

```sh
gh secret set TS_AUTHKEY --repo Derek-X-Wang/wefty          # separate legacy CI key; never a fleet join key
gh variable set TSNET_SMOKE_REQUIRED --repo Derek-X-Wang/wefty --body true
```

Next push to main should show tsnet-smoke actually running (not the
unarmed notice).
