# Dogfood acceptance: v0.1 (single machine) and v0.2 (fleet)

Acceptance is staged to match the rollout plan: prove the loop where it is
cheapest first, then prove the network layer.

- **v0.1 — single machine, plain fabric, no Tailscale.** Control plane, run
  ledger, one agent, and the CLI all on one Mac over localhost. This proves
  everything that is actually new — queue, lease, agent, workflow, envelopes,
  gates, lineage — with zero network prerequisites.
- **v0.2 — fleet, tsnet.** The same workflow pinned to a Mac node and a Linux
  node over a real tailnet. This proves the Fabric seam's production
  implementation and multi-node placement. Nothing else changes: same
  binaries, different `--fabric` flags.

Do not run either lane in CI. Both use the real `claude` and `codex` CLIs.

The workflow is a serial lineage, so one node agent is sufficient: the root
run plans and dispatches the implementation child, the implementation child
commits and dispatches its review child, and L3 holds each parent open until
its descendants settle.

# v0.1 — single-machine acceptance (plain fabric)

## Prerequisites

- One Mac with the accepted wefty commit checked out.
- Node.js 22 or newer, npm, Git, `jq`, `claude`, and `codex` installed;
  both agent CLIs authenticated for non-interactive use.
- The checkout is clean and the acceptance branch name below does not exist.
- No Tailscale, no auth keys, no ACLs.

Plain fabric trusts local processes: each binary self-declares its principal
(CLI = caller, L3 = client, agent = agent), which is the correct trust model
when everything runs as your user on one machine.

Set these in every shell (adjust the checkout path only):

```sh
export WEFTY_ROOT=$HOME/wefty
export WEFTY_STATE_ROOT=/var/tmp/wefty-v0.1
export WEFTY_L1_ADDR=127.0.0.1:42101
export WEFTY_L3_ADDR=127.0.0.1:42102
```

Build everything and run the offline gates once:

```sh
cd "$WEFTY_ROOT"
mkdir -p .bin "$WEFTY_STATE_ROOT"
go build -o .bin/wefty-l1 ./cmd/wefty-l1
go build -o .bin/wefty-l3 ./cmd/wefty-l3
go build -o .bin/wefty-agent ./cmd/wefty-agent
go build -o .bin/wefty ./cmd/wefty

cd workflows/dogfood
npm ci
npm run lint
npm run typecheck
npm test   # fake-agent plain-fabric contract smoke; no LLM calls
npm run build
```

## Start the stack (three terminals)

Terminal 1 — L1 control plane:

```sh
cd "$WEFTY_ROOT"
./.bin/wefty-l1 \
  --fabric=plain \
  --listen="$WEFTY_L1_ADDR" \
  --db="$WEFTY_STATE_ROOT/l1.sqlite" \
  --node-tags=dogfood-local=mac,arm64,wefty:node:dogfood-local
```

Terminal 2 — L3 run ledger:

```sh
cd "$WEFTY_ROOT"
./.bin/wefty-l3 \
  --fabric=plain \
  --listen="$WEFTY_L3_ADDR" \
  --control-plane="$WEFTY_L1_ADDR" \
  --db="$WEFTY_STATE_ROOT/l3.sqlite" \
  --reconcile-interval=1s
```

Terminal 3 — the node agent:

```sh
cd "$WEFTY_ROOT"
mkdir -p "$WEFTY_STATE_ROOT/agent-logs"
./.bin/wefty-agent \
  --fabric=plain \
  --control-plane="$WEFTY_L1_ADDR" \
  --run-ledger="$WEFTY_L3_ADDR" \
  --node-id=dogfood-local \
  --log-spool-dir="$WEFTY_STATE_ROOT/agent-logs"
```

Verify registration before submitting work:

```sh
cd "$WEFTY_ROOT"
./.bin/wefty --l1="$WEFTY_L1_ADDR" --l3="$WEFTY_L3_ADDR" nodes list
```

The table must contain `dogfood-local`, Darwin/arm64, `alive`, with its
reserved `wefty:node:dogfood-local` tag.

## Submit from Claude Code

Run these from the shell tool inside the Claude Code session driving
acceptance. `wefty submit` sends `POST /v1/runs`; the stored inline script is
the small build output, while the runtime loads exactly
`@ai-hero/sandcastle@0.12.0` from the pinned workflow package.

```sh
jq -n \
  --arg task "Add a small, reviewable improvement selected for the v0.1 dogfood run; run focused tests and commit it." \
  --arg repo "$WEFTY_ROOT" \
  --arg package "$WEFTY_ROOT/workflows/dogfood" \
  '{task:$task,repo_path:$repo,workflow_package_path:$package,base_branch:"main",branch:"acceptance/v0.1-local"}' \
  > /tmp/wefty-v0.1-params.json
```

```bash
cd "$WEFTY_ROOT"
set -o pipefail
RUN_ID=$(
  ./.bin/wefty --l1="$WEFTY_L1_ADDR" --l3="$WEFTY_L3_ADDR" --json \
    submit \
    --script=workflows/dogfood/dist/dogfood-workflow.mjs \
    --interpreter=node \
    --params-file=/tmp/wefty-v0.1-params.json \
    --tag=wefty:node:dogfood-local \
    --required-envelope \
    --max-runtime=7200 \
    --idempotency-key=v0.1-dogfood-local \
  | tee /tmp/wefty-v0.1-submit.json \
  | jq -er '.run_id | select(type == "string" and length > 0)'
)
test -n "$RUN_ID"
printf '%s\n' "$RUN_ID"
```

Follow the root log, wait for terminal settlement, then inspect the lineage:

```sh
./.bin/wefty --l1="$WEFTY_L1_ADDR" --l3="$WEFTY_L3_ADDR" logs "$RUN_ID" --follow
./.bin/wefty --l1="$WEFTY_L1_ADDR" --l3="$WEFTY_L3_ADDR" --json inspect "$RUN_ID" \
  | tee /tmp/wefty-v0.1-inspect.json
```

To print every parent and child log after settlement:

```sh
jq -r '.runs[].run_id' /tmp/wefty-v0.1-inspect.json | while read -r run_id; do
  printf '\n===== %s =====\n' "$run_id"
  ./.bin/wefty --l1="$WEFTY_L1_ADDR" --l3="$WEFTY_L3_ADDR" logs "$run_id"
done
```

## v0.1 pass criteria

- `.run.status` is `succeeded` only after both descendants settle.
- `.runs` has exactly three records in lineage order: root `plan`, child
  `implement`, grandchild `review`.
- Every record has one accepted envelope with a non-empty, server-bound
  `attempt_id`; envelope statuses are `succeeded`.
- Every record has one gate with a non-empty `attempt_id`; gate outcomes are
  `pass` (`plan-produced`, `implementation-committed`, `cross-review`).
- Every record has `node_id` equal to `dogfood-local` — run-record evidence
  of placement.
- The implementation envelope contains at least one `git:<sha>` artifact and
  branch `acceptance/v0.1-local` contains that commit. Review corrections, if
  any, appear as `review-fix` artifacts on the same branch.
- Logs show the plan, Codex implementation, Claude review, and child run IDs.
  Logs do not contain the run token; any accidental occurrence is
  `[REDACTED]`.

Mechanical check:

```bash
jq -e --arg node dogfood-local '
  .run.status == "succeeded" and
  (.runs | length) == 3 and
  ([.runs[].envelopes[0].step_id] == ["plan","implement","review"]) and
  ([.runs[].envelopes[0].status] | all(. == "succeeded")) and
  ([.runs[].gates[0].outcome] | all(. == "pass")) and
  ([.runs[].node_id] | all(. == $node)) and
  ([.runs[].envelopes[0].attempt_id] | all(length > 0)) and
  ([.runs[].gates[0].attempt_id] | all(length > 0))
' /tmp/wefty-v0.1-inspect.json
```

Record the root run ID, accepted commit, inspection JSON, and any review-fix
SHAs in issue #30. A failed/errored gate, missing envelope, failed
descendant, absent logs, wrong node, or real CLI invocation failure fails
acceptance and must not be papered over by tagging.

## Tag v0.1

After the evidence is attached to issue #30 and every criterion passes:

```sh
cd "$WEFTY_ROOT"
git tag -a v0.1 -m "wefty v0.1: dogfood loop accepted single-machine (plain fabric)"
git push origin v0.1
```

# v0.2 — fleet acceptance (tsnet, one Mac + one Linux)

Run this after v0.1 is tagged and when the fleet phase starts. It is the
original two-node lane: same binaries and workflow, `--fabric=tsnet`, work
pinned once to a Mac node and once to a Linux node.

## Additional prerequisites

- The same accepted commit checked out on the control-plane host and on both
  agent machines; Node 22+, npm, Git, `jq`, `claude`, `codex` on both agents.
- Four reusable tsnet auth keys: `TS_AUTHKEY_CONTROL`, `TS_AUTHKEY_CLIENT`
  (tagged `tag:wefty-client`), `TS_AUTHKEY_AGENT_MAC`, and
  `TS_AUTHKEY_AGENT_LINUX` (both tagged `tag:wefty-agent`).
- Tailnet ACLs allow the client and agent identities to reach
  `wefty://control-plane` and `wefty://run-ledger` on their internal port 80.

```sh
export WEFTY_CONTROL_ROOT=/srv/wefty
export WEFTY_MAC_ROOT=$HOME/wefty
export WEFTY_LINUX_ROOT=/srv/wefty
export WEFTY_STATE_ROOT=/var/tmp/wefty-v0.2
export TS_CONTROL_URL="${TS_CONTROL_URL:-}"
```

Build on each host exactly as in v0.1 (control host: l1/l3/CLI; each agent
machine: `wefty-agent` plus the workflow package gates).

## Start the tsnet stack

Control-plane host, terminal 1:

```sh
cd "$WEFTY_CONTROL_ROOT"
./.bin/wefty-l1 \
  --fabric=tsnet \
  --listen=wefty://control-plane \
  --fabric-name=wefty://control-plane \
  --state-dir="$WEFTY_STATE_ROOT/l1-tsnet" \
  --auth-key="$TS_AUTHKEY_CONTROL" \
  --control-url="$TS_CONTROL_URL" \
  --db="$WEFTY_STATE_ROOT/l1.sqlite" \
  --node-tags=dogfood-mac=mac,arm64,wefty:node:dogfood-mac \
  --node-tags=dogfood-linux=linux,amd64,wefty:node:dogfood-linux
```

Control-plane host, terminal 2:

```sh
cd "$WEFTY_CONTROL_ROOT"
./.bin/wefty-l3 \
  --fabric=tsnet \
  --listen=wefty://run-ledger \
  --control-plane=wefty://control-plane \
  --fabric-name=wefty://run-ledger \
  --state-dir="$WEFTY_STATE_ROOT/l3-tsnet" \
  --auth-key="$TS_AUTHKEY_CLIENT" \
  --control-url="$TS_CONTROL_URL" \
  --db="$WEFTY_STATE_ROOT/l3.sqlite" \
  --reconcile-interval=1s
```

Mac agent:

```sh
cd "$WEFTY_MAC_ROOT"
mkdir -p "$WEFTY_STATE_ROOT/mac-agent"
./.bin/wefty-agent \
  --fabric=tsnet \
  --control-plane=wefty://control-plane \
  --run-ledger=wefty://run-ledger \
  --node-id=dogfood-mac \
  --fabric-name=wefty://node/dogfood-mac \
  --state-dir="$WEFTY_STATE_ROOT/mac-agent/tsnet" \
  --log-spool-dir="$WEFTY_STATE_ROOT/mac-agent/logs" \
  --auth-key="$TS_AUTHKEY_AGENT_MAC" \
  --control-url="$TS_CONTROL_URL"
```

Linux agent:

```sh
cd "$WEFTY_LINUX_ROOT"
mkdir -p "$WEFTY_STATE_ROOT/linux-agent"
./.bin/wefty-agent \
  --fabric=tsnet \
  --control-plane=wefty://control-plane \
  --run-ledger=wefty://run-ledger \
  --node-id=dogfood-linux \
  --fabric-name=wefty://node/dogfood-linux \
  --state-dir="$WEFTY_STATE_ROOT/linux-agent/tsnet" \
  --log-spool-dir="$WEFTY_STATE_ROOT/linux-agent/logs" \
  --auth-key="$TS_AUTHKEY_AGENT_LINUX" \
  --control-url="$TS_CONTROL_URL"
```

Verify both registrations (`dogfood-mac` Darwin/arm64, `dogfood-linux`
Linux/amd64, both `alive` with their reserved tags):

```sh
cd "$WEFTY_CONTROL_ROOT"
./.bin/wefty \
  --fabric=tsnet \
  --fabric-name=wefty://node/dogfood-operator \
  --state-dir="$WEFTY_STATE_ROOT/operator-tsnet" \
  --auth-key="$TS_AUTHKEY_CLIENT" \
  --control-url="$TS_CONTROL_URL" \
  nodes list
```

## Submit, verify, tag

Repeat the v0.1 submit/inspect/criteria flow twice with the tsnet CLI flags
above instead of `--l1/--l3`: once with `--tag=wefty:node:dogfood-mac`
(params `repo_path`/`workflow_package_path` pointing at `WEFTY_MAC_ROOT`,
branch `acceptance/v0.2-mac`, idempotency key `v0.2-dogfood-mac`) and once
with `--tag=wefty:node:dogfood-linux` (Linux paths, branch
`acceptance/v0.2-linux`, key `v0.2-dogfood-linux`). Interpreter stays
`--interpreter=node` so the path resolves on the agent node, never the
control host.

Pass criteria are identical to v0.1 per run, with `node_id` checked against
`dogfood-mac` and `dogfood-linux` respectively. Attach both evidence sets to
the fleet-phase tracking issue, then:

```sh
cd "$WEFTY_CONTROL_ROOT"
git tag -a v0.2 -m "wefty v0.2: dogfood workflow accepted on tsnet fleet (macOS + Linux)"
git push origin v0.2
```
